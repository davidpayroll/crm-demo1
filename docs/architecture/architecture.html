Architecture

Australian Payroll Advisory (APA)

Technical companion to the product plan

1. Overview

This is a Next.js (App Router) app deployed on Vercel, backed by a Supabase Postgres database, with Resend for email. It has two surfaces: a public marketing site that captures leads, and an /admin CRM. /admin starts open and gets locked down with Supabase Auth later in the build.

2. How the pieces fit

  • Next.js (App Router) — renders the public site and /admin; server code handles form submissions and all database reads/writes.
  • Vercel — hosts and deploys the app; environment variables hold every secret; a push deploys.
  • Supabase (Postgres) — the database. Accessed server-side only, using the service key. Secrets never reach the browser.
  • Resend — sends the confirmation email when a lead comes in (wired in Build 2).

Environment variables

VariableWhat it's for
NEXT_PUBLIC_SUPABASE_URLThe Supabase project's API endpoint.
NEXT_PUBLIC_SUPABASE_ANON_KEYPublic client key — safe to expose in the browser, limited by row-level security.
SUPABASE_SERVICE_ROLE_KEYServer-only key with full database access — used for all reads/writes; never sent to the client.
RESEND_API_KEYAuthenticates outbound email sending through Resend.
NEXT_PUBLIC_SITE_URLThe live domain — used for email links and redirects.

3. The lead flow

  1. Visitor submits the contact form on the public site.
  2. Server upserts a People row by email — never duplicates a person.
  3. Server creates a linked Contacts row in status new_lead.
  4. (Build 2) Resend sends a confirmation email to the visitor.
  5. Operator sees and works the lead in /admin.
  6. Each status change on the Contacts row writes an activity_log row.

  • One Contacts row has many activity_log rows.
